# 声控逃亡：声音控制规格 v0.1

更新时间：2026-08-13
状态：技术 Spike 基线，参数待真机验证

## 1. 技术目标

把玩家稳定发出的舒适高音和低音映射为两个离散动作。系统不识别字义，音量只用于判断是否正在发声，不控制角色速度。

推荐玩家使用持续元音或哼声，例如"啊、呜、咿、嗯"。耳语、吹气、拍手和清辅音没有稳定基频，不作为支持输入。

## 2. 本地处理链路

RecorderManager PCM
→ Int16 归一化
→ 环形缓冲
→ 去直流 / 60Hz 高通
→ RMS 与动态噪声底
→ VAD 有声判断
→ YIN 基频 F0 检测
→ 置信度与连续性过滤
→ 个人音域分类
→ 边沿触发状态机
→ 角色动作门控

首轮采集参数：

|||
|---|---|
|格式|PCM 16-bit|
|采样率|16000Hz|
|声道|Mono|
|平台回调块|优先 1KB，不稳定则 2KB|
|环形缓冲|4096 samples|
|分析窗口|1024 samples / 64ms|
|Hop size|256 samples / 16ms|
|F0 搜索范围|70–1000Hz|
|算法|YIN|
|YIN threshold|0.15|
|最低置信度|0.80|


不使用 FFT 最大峰值直接判断音高，以避免元音高次谐波导致倍频或半频误判。平台音频回调先写入环形缓冲，不能假设每个回调块刚好等于分析窗口。

## 3. VAD 与噪声处理

首轮阈值思想：

vadOn  = 动态噪声底 + 约 10dB
vadOff = vadOn - 约 4dB

- 噪声底只在无声状态缓慢更新。
- 响度达标且音高置信度达标，才进入分类。
- 一段声音中的有效音高帧低于约 60% 时不分类。
- 连续约 2 秒环境过吵或低置信度时暂停计分并提示，不随机控制角色。
- BGM 不使用人声或持续纯音，声控期间默认降低外放音量。
旁人说话、电视和短视频外放同样可能有稳定基频，无法仅靠本地音高算法完全排除。产品目标环境首先限定为安静或轻度背景噪声，并以真机数据决定是否扩大承诺。

## 4. 个人音域校准

首轮可靠性流程：

静音 1.2 秒
→ 舒适低音 3 次，每次 0.4–0.8 秒
→ 舒适高音 3 次，每次 0.4–0.8 秒
→ 计算低音中心 L 与高音中心 H
→ 各触发一次动作确认

单段样本要求：

- 有效有声时长至少 300ms
- 有效音高帧占比至少 70%
- 段内音高中位绝对偏差不高于约 80 cents
- 信噪比至少约 10dB
使用对数音高：

const cents = 1200 * Math.log2(f0 / 440);

校准初始通过条件：

- H - L >= 400 cents，即至少约 4 个半音
- 同组样本离散度不高于约 150 cents
- 两组均处于 70–1000Hz
- 不针对男性、女性或儿童设置固定阈值
分类半径初值：

const gap = highCenter - lowCenter;
const radius = clamp(gap * 0.35, 150, 300);

输入必须靠近一个个人中心，同时明显远离另一个中心才接受，其余作为中性或无效输入。连续两次校准失败后提供触控模式，不要求玩家反复发声。

Spike 使用三次样本优先验证可靠性。减少样本、把校准融入教学属于后续漏斗优化，不能在没有数据时提前牺牲准确率。

## 5. 触发状态机

ARMED
├─ 稳定高音达到约 64ms → emit JUMP → LOCKED_HIGH
└─ 稳定低音达到约 64ms → emit ROLL → LOCKED_LOW

LOCKED_HIGH / LOCKED_LOW
└─ 静音或中性持续至少 120ms
   且距上次指令至少 450ms
   → ARMED

游戏门控：

- 只有落地且角色当前可执行动作时才接收命令。
- 非法状态下的命令丢弃，不进入队列。
- 跳跃冷却初值 600ms，翻滚冷却初值 650ms。
- 同一段持续发声最多触发一个动作。
- 高音直接滑向低音时不能连续触发。
- 碰撞判定可以提供约 150–200ms的输入宽容，但不能掩盖动作视觉时序。
端到端目标：

|||
|---|---|
|有声起点到命令 P50|<150ms|
|有声起点到命令 P95|<280ms|
|命令事件到画面动作|<1 frame|


## 6. 权限、异常和降级

- 只有用户主动点击开始后才申请麦克风权限。
- 权限被拒时不连续弹窗，提供一次用途说明和"重新授权 / 触控体验"。
- 基础库或设备不支持 PCM 时直接进入触控体验模式。
- 切后台、来电或录音中断时暂停关卡、停止录音、清空缓冲和触发状态。
- 返回前台由用户主动恢复，重新测约一秒噪声底，个人音域模板可复用。
- Recorder 异常只自动重启一次，再失败则暂停并降级。
- 连续三次有声但无有效音高时，提示使用持续元音。
- 低端机积压时先关闭波形动画，再把 Hop 调到 512；仍积压则降级。
- 声控与触控成绩用 controlMode 分开，不能混入同一竞争榜。
## 7. 隐私与日志

生产环境不记录：

- 原始 PCM 或语音片段
- 用户自由文本
- 可还原语音内容的逐帧数据
建议记录匿名事件：

mic_permission_request / result
audio_stream_start / error
calibration_start / sample_result / result
command_detected / rejected
action_executed
audio_interrupted
fallback_entered
run_audio_summary

运行汇总只保存设备档位、基础库版本、回调间隔、处理耗时、有效音高率、高低音检测与执行数量、拒绝原因、延迟分位数、缓冲丢弃和降级原因。

Spike 调试版可以在测试者明确同意后导出 timestamp / RMS / F0 / confidence / class / groundTruth，仍不保存原始录音。

## 8. 两天技术 Spike

### 第一天：检测器

- 真机获取 PCM，显示 RMS、噪声底、F0、置信度和分类。
- 完成个人高低音校准、YIN、分类器和触发状态机。
- 至少验证 2 台 Android 和 2 台 iPhone。
### 第二天：动作闭环

- 接入仅有高、低两类障碍的 30 秒固定关卡。
- 随机提示高音、低音、静音，并由测试者标记真实意图。
- 至少 8 人，每人各完成 20 次高音和 20 次低音。
- 补测安静、普通手机外放、附近交谈三种环境。
- 输出按人、设备和环境拆分的召回率、准确率、交叉误判、误触与延迟。
进入完整开发的内部技术门槛：

- 校准首轮成功率至少 80%，重试后至少 90%
- 校准中位时间低于 30 秒
- 安静环境指令召回率至少 90%
- 安静环境指令准确率至少 95%
- 高低音交叉误判低于 3%
- 普通室内背景下准确率至少 85%
- 安静状态误触不高于 1 次/10 分钟
- 背景交谈误触不高于 1 次/3 分钟
- 延迟 P50 <150ms、P95 <280ms
- 低端机连续运行 3 分钟无明显积压、掉帧或录音中断
- 至少 80%新玩家在两局内正确完成全部高低音障碍

若交叉误判超过 5%、多数用户无法在 30 秒内完成校准，或端到端 P95 超过 350ms，暂停完整游戏开发，先处理输入方案。
