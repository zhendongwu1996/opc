# 声控逃亡：验证与止损计划 v0.1

更新时间：2026-08-13
实验周期：最多 14 天
现金预算：最多 3000 元

本文件中的数字均为项目内部决策阈值，不是抖音小游戏行业基准。小样本阶段需要结合行为录像、访谈和漏斗趋势判断。

## 1. 要验证的链路

短视频吸引进入
→ 用户愿意授权麦克风
→ 用户顺利完成校准
→ 声控可靠且失败可归因
→ 用户连续挑战距离
→ 纪录驱动分享或回访
→ 广告不明显破坏体验

必须按顺序验证。前一项不成立时，不用美术、养成或广告掩盖问题。

## 2. 核心假设优先级

- 输入可用性：不同人声、手机和普通噪声环境下能够稳定区分高低音。
- 授权与场景成立：用户愿意授权，并愿意在真实使用环境中发声。
- 核心循环成立：新鲜感过后，用户仍会主动开启第二局和第三局。
- 传播成立：看别人玩能转化为自己进入游戏，而不仅是观看表演。
- 纪录驱动成立：距离和同图挑战能提高重开、分享或回访。
- 轻量变现成立：死亡续命广告不会明显损害继续游玩意愿。
## 3. 分阶段闸门

|||||
|---|---|---|---|
|技术可行性|D1–D2|8–30 人，多设备与环境|重试后校准 >=90%；脚本动作识别 >=90%；交叉误判 <3%；P95 <280ms；多数失败被认为是操作问题|
|授权与上手|D3–D4|30–50 位非项目相关用户|授权率 >=70%；校准完成 >=85%；教程完成 >=70%；打开到首局中位 <45s|
|核心玩法|D5–D7|50–100 位新用户|二局开启 >=55%；三局开启 >=35%；有效游玩中位 >3min；主动重开 >=50%|
|分发转化|D8–D10|15–20 条素材，尽量获得 100 次可归因启动|素材进入率目标 >=1%；至少 2 条达到素材中位数约 2 倍；进入后有效开局 >=60%|
|分享与回访|D10–D13|尽量达到 200–300 位有效新用户|分享意图 >=5%；D1 有效回访目标 >=20%；新纪录明显提高重开率|
|轻量变现|D12–D14|仅在前序成立后测试|续命广告选择目标 >=15%；广告后立即退出 <15%；加入广告后重开下降不超过约 10 个百分点|


每阶段最多允许一次、最多一天的针对性修正。仍未通过时停止或明确转型。

## 4. 14 天执行节奏

- D1：核对平台麦克风、隐私与发布要求；实现真机音高检测。
- D2：完成多人声、多设备、多环境测试并通过技术闸门。
- D3–D4：完成权限说明、校准、教学和基础埋点。
- D5–D7：完成跑道、障碍、追捕容错、结算重开和个人纪录。
- D8–D10：制作并测试 15–20 条不同钩子的真实玩法素材。
- D10–D12：观察连续游玩、分享和次日回访，只修复漏斗最大问题。
- D12–D14：前序成立后才加入一次激励续命实验并完成项目决策。
平台审核周期不受控制时，可以先用测试版验证玩法，但不能把测试版流量等同于抖音正式分发能力。

## 6. 指标定义

- 麦克风授权率 = 授权用户数 / 看到授权请求的用户数
- 校准完成率 = 完成校准用户数 / 开始校准用户数
- 有效新用户 = 首次进入、完成校准并启动至少一局的用户
- 有效开局率 = 启动至少一局的新用户数 / 新进入用户数
- 二局开启率 = 启动第二局用户数 / 完成第一局用户数
- 三局开启率 = 启动第三局用户数 / 有效新用户数
- 主动重开率 = 不看广告再次开局人数 / 已结束首局人数
- 有效游玩时长 = 会话中所有跑酷时间之和，不含校准、停留和广告
- 素材进入率 = 对应素材带来的打开数 / 可归因有效曝光数
- 分享意图率 = 点击分享人数 / 有效新用户数，不等同于分享成功
- D1 有效回访率 = 首次有效开局后 24–48 小时再次开局人数 / 已满观察窗口的新用户数
- 广告后立即退出率 = 广告完成后未恢复操作人数 / 广告完成人数
## 7. 必须保留的对照

内部保留同关卡的触控对照版，用上滑跳、下滑滚或两个临时按钮控制。它不用于替代声控，而用于回答最关键的问题：


声控是否真的比两个触控按钮带来更高的重玩或分享？

若声控版只是更难、更不稳定，而重玩和分享没有明显改善，则声控只能算噱头。

## 8. 立即止损条件

- 调整一次后，识别可靠性或延迟仍未通过技术门。
- 多数用户认为失败来自系统误判。
- 用户喜欢看演示，却明显拒绝授权或不愿在真实环境中发声。
- 第三局率和有效游玩时间弱，且只能依赖养成或大量内容补救。
- 20 条有实质区别的素材仍无法稳定带来有效开局。
- 流量主要依赖夸张尖叫、整蛊或风险内容。
- 距离新纪录没有提高重开、分享或回访意愿。
- 广告显著损害重开行为。
- 超过 14 天或 3000 元仍无法判断一个核心假设。

最终只做四种决策：继续开发、只迭代一次、转为触控跑酷并重新立项、停止项目。
